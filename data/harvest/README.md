# Commons harvest

The harvester ([`whereabout_ml.harvest`](../../ml/src/whereabout_ml/harvest.py)) finds new game
photos on Wikimedia Commons and screens them by machine instead of by eye. The files here are
generated by the [Commons harvest workflow](../../.github/workflows/harvest.yml); they are not
hand-edited. The same workflow then adds harvested photos to the game catalog (see *Into the
game* below).

| File | Contents |
| --- | --- |
| `harvested.csv` | Photos that passed every check, in `photos.csv` columns, ids `wh<Commons page id>` |
| `manifest.csv` | Provenance per harvested photo: page id, title, grid cell, seed place, Commons assessment, original size, distance to the named place, pHash, scene-gate scores |
| `rejected.csv` | `title`, `stage` (`metadata`, `ingest`, `scene_gate`, `place`), `reason` for every candidate that was dropped |
| `report.json`, `report.md` | The funnel: counts per stage and per reason, settings, model, licenses |

## Pipeline

1. **Seeds.** The world is cut into 10° x 10° cells. In each cell with GeoNames places
   (`cities15000`, CC BY 4.0), up to 12 are drawn at random with a fixed seed (`seeds_per_cell`).
2. **Discover.** Commons geosearch lists files whose camera location is within 10 km of a seed.
   Only files in *Quality images* or *Featured pictures on Wikimedia Commons* are kept (both
   categories are added by Commons' own assessment templates, so each file passed a community
   review of technical quality). At most 30 per cell go on (`candidates_per_cell`), featured
   first; titles already in the catalog are skipped.
3. **Metadata.** JPEG, at least 1280 px wide (the catalog links the 1280 px rendition),
   landscape (width at least 1.25 x height), and the [ingestion checks](../ingest/README.md):
   an allowed license (CC0, public domain, CC BY, CC BY-SA), an author to credit, no
   personality-rights tag, camera coordinates. License, author and source page come from the
   Commons API's `extmetadata`.
4. **Dedupe.** A 330 px thumbnail of every candidate is hashed (64-bit pHash) together with the
   catalog's own files. A candidate within 8 bits of a catalog photo is dropped; of two
   near-identical candidates the larger original is kept. A thumbnail that cannot be downloaded
   after retries is rejected here too, without stopping the run.
5. **Scene gate.** The [CLIP scene gate](../scene_gate/README.md) scores the same thumbnail with
   the thresholds and the CLIP model recorded in `data/scene_gate/thresholds.json`. A photo that
   reaches any threshold (people, indoor, text, not a photo, a close-up of an animal or plant) is
   rejected. The thresholds were
   calibrated on the hand-reviewed catalog photos at 1280 px; CLIP sees a 224 px crop either way.
6. **Place.** The nearest GeoNames place gives the country and the place shown at the reveal:
   "Town, Country", or "near Town, Country" when the camera is more than 15 km away. A photo more
   than 150 km from every place is dropped. Near borders the country can be wrong; the nearest
   place is an approximation.
7. **Balance.** Photos are added until the catalog would hold the target (1,000 by default),
   always from the cell with the fewest photos so far, catalog photos included, and at most 15 per
   cell (`max_per_cell`). Within a cell, featured pictures come first, then larger originals.

Every number in `report.md` comes from the workflow's run against the live Commons API.

The first run searched 4 places and kept 12 candidates per cell, and harvested 307 photos
(1,046 assessed files found near 820 seeds): finding files was the bottleneck, so the defaults
above are wider. All of them, the target and the merge limit are inputs of the workflow when it
is run by hand. That first harvest predates the close-up reason, and many of its photos are
birds, insects and flowers, so none of it went into the game; the next run screens again.

## Into the game

After harvesting, [`merge-harvest`](../../ml/src/whereabout_ml/merge_harvest.py) appends every
harvested photo that is not in `data/curation/photos.csv` yet, in `harvested.csv` order. The
optional `merge_limit` input caps a run; that order is the grid-balancing order, so a capped
merge still spreads across the map and the next run continues where it stopped. A malformed row
fails the merge before anything is written. The workflow rebuilds the bundled `web/src/data/photos.json`, commits, and
starts the workflows that derive from the catalog: photo quality, concept labels and Atlas.

The game only deals photos Atlas has guessed (`web/src/lib/game/playable.ts`; the API follows
the same rule), so a merged photo starts appearing in games once the Atlas workflow has run on
it. Merges were capped at 150 photos to keep that run inside the runner's time limit. The Atlas
workflow now caches image embeddings (only new photos are encoded) and gives new saliency maps a
90-minute budget per run, queueing another run for the photos still without a map, so every new
photo is guessed in the first run and a whole harvest can join the game at once.

Merged photos keep their `wh` ids and are machine-screened, not reviewed by eye; the scene gate
keeps calibrating on the hand-reviewed `wm` photos only.
